DeepSeek V4.1-Flash-1017은 2026년 10월 17일 공개된 업데이트다. API에서는 `deepseek-flash`라는 이름을 유지한 채 새 모델을 제공한다. 호출 이름을 그대로 쓴다고 결과도 그대로인 것은 아니다. 모델이 바뀌면 우리 업무의 정답 조건을 다시 확인해야 한다.

같은 가격의 모델 업데이트는 점수표가 아니라 도구가 들어간 업무 흐름으로 확인해야 한다. 공급자 Terminal-Bench 4는 31.2에서 42.3으로 11.1퍼센트포인트 상승했다. 이는 11.1% 상승과 다르다. 같은 자료의 DeepSWE는 74.2에서 77, Automation-Bench는 54.8에서 60.5다. 10월 27일 Vals의 별도 Mini-SWE-agent 평가에서는 Flash-1017이 31.82%, 테스트당 $0.54이고 이전 Flash는 19.70%, $0.50이다. 공급자 TB4의 Claude Code 하네스와 Vals의 Mini-SWE-agent 결과를 섞어 하나의 순위로 만들 수는 없다. Vals는 66개 작업을 세 번씩 실행한 avg@3 조건이다.

| 평가 주체와 도구 환경 | 이전 Flash | Flash-1017 | 읽을 때 주의할 점 |
|---|---:|---:|---|
| DeepSeek, Claude Code / Terminal-Bench 4 | 31.2% | 42.3% | 공급자 평가, 11.1%포인트 상승 |
| Vals, Mini-SWE-agent / Terminal-Bench 4 | 19.70% | 31.82% | 별도 평가의 세 번 실행 평균 |

하네스는 모델에 작업과 도구를 연결하는 실행 프로그램이다. 사용하는 도구, 지시문, 중단 조건이 달라지면 같은 모델도 다른 결과를 낸다. 두 행을 가로질러 점수를 빼기보다 각 행 안에서 이전 모델과 새 모델을 비교해야 한다.

## 환불 판단은 모델만의 일이 아니다

공개된 환불 판단 예제에서는 12일 전 구매한 미사용 상품을 입력으로 둔다. 정책은 구매 후 30일 이내이면서 미사용일 때만 적용한다. 모델 호출은 최대 네 번으로 제한하고, 읽기 전용 `get_refund_policy`의 호출 이름과 인자 없음, JSON의 `eligible` 값과 타입, `policy_id`를 정책 조회 결과에 다시 대조한다. 실제 환불 이체는 하지 않는다. `eligible`은 가능 여부를 나타내는 참·거짓 값이고 `policy_id`는 적용한 규칙의 식별자다. JSON은 프로그램이 항목별로 읽을 수 있는 데이터 형식이다. 정책 조회가 실제로 일어났는지와 응답 항목의 자료형도 검사해야 한다. 모델은 후보 판단을 만들고, 정책과 애플리케이션 검증은 그 판단이 업무 규칙과 맞는지 확인한다.

아래는 내가 다음 평가에 추가할 경계 사례다. 실제로 실행한 결과표가 아니다. 구매일이 없는 경우의 추가 질문은 기존 예제를 확장하는 설계다.

| 입력 | 기대 결과 | 확인 |
|---|---|---|
| 30일, 미사용 | eligible=true | 날짜 경계와 정책 ID |
| 31일, 미사용 | false | 경계 초과 |
| 기간 안, 사용함 | false | 사용 상태 |
| 구매일 없음 | 추가 질문 | 추측 금지 |

Youssef Hosni가 10월 23일 기록한 이 예제의 한 실행은 모델 호출 2회, 전체 반복 처리 시간 2.312초였다. 입력 855토큰 중 256토큰이 캐시였고 출력은 154토큰이었다. 한 사례가 성공했다는 기록이지, 환불 판단의 평균 정확도나 서비스 지연 시간을 입증한 결과는 아니다.

## 예산과 신뢰도를 따로 적는다

2026년 10월의 비교에 사용한 API 요금은 다음과 같다. 단위는 미국 달러이며 토큰 100만 개당 가격이다.

| 시간대 | 새 입력 | 캐시 입력 | 출력 |
|---|---:|---:|---:|
| 피크 | $0.30 | $0.006 | $1.20 |
| 오프피크 | $0.15 | $0.003 | $0.60 |

당시 피크는 중국 공휴일을 제외한 평일 UTC 01–04시와 06–10시였다. 그 밖의 시간에는 오프피크 요금을 적용한다. 캐시는 앞서 처리한 입력을 재사용하는 할인이다. 캐시 없는 입력 100만 토큰과 출력 10만 토큰이면 $0.30 + $0.12 = $0.42다. 오프피크에는 $0.21이며 재시도와 별도 도구 비용은 제외한 계산이다. 같은 답을 얻는 데 필요한 사용량이 모델마다 다르므로, 이 계산만으로 전체 업무 비용을 비교할 수는 없다.

내가 배포 여부를 판단한다면 같은 테스트 묶음으로 이전 버전과 새 버전을 비교하고, 정답률과 재시도 횟수, 사람의 수정 시간을 함께 남기겠다. 긴 입력을 받을 수 있다는 사양은 필요한 규칙을 빠짐없이 찾아낸다는 보장이 아니다. 반환 형식과 업무 판단을 따로 검사해야 모델 업데이트 뒤의 오류를 찾을 수 있다.
